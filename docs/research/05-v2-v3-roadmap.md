# V2 / V3 后续路线

V1 已保留稳定 project ID、evidence refs、`extensions` 命名空间和事件前缀，但不创建空壳能力。

## V2：项目生成器

独立 Skill：`stm32-project-builder`。

输入示例：“我要做智能车”，同时补充芯片、板卡、现有器件、预算、环境、安全和时间约束。输出方案、器件/BOM、接线、分阶段代码和验证计划。生成采用 manifest 与最小可编译增量，不一次倾倒不可验证的全工程；写 `generation.*` 并引用 V1 学习证据。

## V3：比赛导师

独立 Skill：`stm32-competition-mentor`。

输入竞赛规则、时间、队伍、题目约束和现有原型。输出选题候选、创新点证据状态、技术路线、BOM、实验、论文和答辩材料。创新点必须能追溯检索/实验依据；论文保留学生决策与推理；写 `competition.*`。

## 版本演进原则

- V2/V3 复用 V1 的掌握度和证据，不复制状态真相。
- 内容升级不改写已完成历史；目录迁移显式执行。
- 新事件命名空间互不覆盖，V1 对未知扩展原样保留。
- 高风险硬件和真实比赛规则仍需权威来源与人工确认。
